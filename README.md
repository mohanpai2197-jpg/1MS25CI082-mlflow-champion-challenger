# Champion-Challenger Model Comparison (MLflow)
**1MS25CI082-mlflow-champion-challenger**  
*Skill Lab (MLOps with MLflow) · Mini Project: Champion-Challenger Model Comparison with Hugging Face and MLflow*

## Overview
Two pretrained Hugging Face extractive question-answering models are evaluated on the same 100 SQuAD v2 questions. Every run, parameter, metric, plot, and model artifact is tracked in MLflow. A Champion rule fixed before the final run determines the winner. Both models are registered in the MLflow Model Registry under `qa-model` with `champion` and `challenger` aliases. Predictions on new unseen questions are generated by loading `models:/qa-model@champion` strictly through MLflow pyfunc without directly importing Hugging Face Transformers.

## 1. Task and Models
| Item | Value |
|---|---|
| **Task** | Extractive question answering (SQuAD v2 – includes unanswerable questions) |
| **Dataset** | `rajpurkar/squad_v2`, `validation` split |
| **Subset** | 100 questions, `shuffle(seed=42)` → 48 answerable, 52 unanswerable |
| **Model A (current Champion)** | `deepset/minilm-uncased-squad2` (~33M params) → run `A_qa_minilm-squad2` |
| **Model B (Challenger)** | `deepset/roberta-base-squad2` (~125M params) → run `B_qa_roberta-base-squad2` |
| **Summary run** | `compare_qa` (parent run; A and B are nested runs) |
| **Experiment** | `hf-qa-champion-challenger` |
| **Registered model** | `qa-model` |

Both models use identical inference settings:
- `max_seq_len`: 384
- `doc_stride`: 128
- `max_answer_len`: 30
- `handle_impossible_answer`: True
- Device: CPU (`device=-1`)

---

## 2. Champion Rule (Fixed Before Final Run)
- **Primary metric**: SQuAD v2 F1 score (token-level overlap, averaged over all 100 questions; higher is better).
- **Minimum improvement margin**: Challenger (Model B) must beat Champion (Model A) by at least **2.0 F1 points** (`margin = 2.0`). Anything under 2.0 points is considered noise.
- **Tie-breaker**: If difference in F1 is within $\pm 2.0$ points, keep the faster model (lower `avg_latency_ms`).
- **Latency guardrail**: Reject Challenger if its average latency is more than **$5\times$** that of the Champion (`latency_guardrail_x = 5.0`).
- **Metric directions**:
  - `exact_match`, `f1`, `has_ans_f1`, `no_ans_accuracy` → higher is better
  - `avg_latency_ms`, `total_inference_s` → lower is better

## 4. Setup and Execution

### Step 1: Environment Setup
```bash
python -m venv venv
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

pip install -r requirements.txt
```

### Step 2: Start MLflow Tracking Server (Terminal 1)
```bash
python -m mlflow server --host 127.0.0.1 --port 5000 --backend-store-uri sqlite:///mlflow.db
```

### Step 3: Run Evaluation Pipeline (Terminal 2)
```bash
# Debug run (optional):
# EVAL_SAMPLES=10 python evaluate.py

# Full run on 100 questions:
python evaluate.py
```

### Step 4: Register Models & Set Aliases
```bash
python register_champion.py
```

### Step 5: Run Inference via MLflow Model URI
```bash
python predict_from_mlflow.py
```

### Stretch Goal: Flip Aliases and Re-evaluate
```bash
python register_champion.py --flip
python predict_from_mlflow.py
python register_champion.py --flip
```

## 5. Results Summary
| Metric | Direction | Model A (MiniLM) | Model B (RoBERTa-base) | B − A |
|---|---|---|---|---|
| **F1 (primary)** | higher | **83.10** | 82.30 | **−0.80** |
| **Exact Match** | higher | **80.00** | 79.00 | −1.00 |
| **F1 on answerable (48)** | higher | 83.54 | **86.04** | +2.50 |
| **No-answer accuracy (52)** | higher | **82.69** | 78.85 | −3.84 |
| **Avg latency (ms / question)** | lower | **102.17** | 332.22 | +230.05 ($3.25\times$) |
| **Total inference time (s)** | lower | **10.22** | 33.22 | +23.00 |

### Decision
Model A (`deepset/minilm-uncased-squad2`) **remains Champion**. The Challenger's F1 score difference is within the $\pm 2.0$ margin ($-0.80$ F1 points), activating the tie-breaker which picks the faster model ($102.17\text{ ms}$ vs $332.22\text{ ms}$).
